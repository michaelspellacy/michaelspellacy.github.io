Captions not loading when loading="lazy" is present on video element.

Issue:
Following the introduction of native lazy loading for video and audio elements in Chrome 148, track elements (captions/subtitles) no longer load when loading="lazy" is present on the parent video. This is a regression from prior behavior, where loading="lazy" was silently ignored on video elements and tracks loaded normally. The track element's readyState remains 0 (NONE) and no network request for the VTT file is made, even after the video scrolls into view and begins loading its source. The issue does not reproduce in Firefox, where lazy loading for video is not yet implemented.
Platform(s):
Chrome: Version 149.0.7827.54 (Official Build) (64-bit)

Steps to Duplicate Issue

  1. Create a video element with loading="lazy", a source pointing to a valid MP4, and a track pointing to a valid VTT file.
  2. Load the page in Chrome 148 or later.
  3. Scroll the video into view, press play, and observe the lack of captioning, which should load by default.

Video with locding="lazy"

Video without locding="lazy"

Expected

Captions and subtitles are available and the VTT file is fetched once the video enters the viewport.

Actual

No VTT request is made, track.readyState stays 0, and captions, which are set to show by default, are absent from native controls.

Workaround

Remove loading="lazy" from the video element.
